# Related projects and implementation choices

Reviewed 2026-10-14. Discovery started at https://git.hiwiki.org/zh-CN and its Android category; candidate capabilities were verified at upstream repositories. This list does not claim all candidates are indexed by the directory. Popularity alone is not a suitability or accuracy measure.

## Joplin — memory retrieval

https://github.com/laurent22/joplin
https://joplinapp.org/help/apps/search/

Upstream documents date, tag and type filters, full-text search and a separate search mode for Chinese and other languages without Latin word boundaries. LifeMemory borrows the explicit-filter interaction, independently implemented in Java. It does not embed Joplin or copy source code. Current retrieval still scans local records; it is not FTS or vector search.

Implemented: type:audio/photo/text/context, topic:NAME (exact, case-insensitive, no spaces), pinned:true/false, period:morning/midday/afternoon/evening, combinable with keywords and dates. Yesterday evening / 昨天晚上 filters by the same device-local period boundaries as the timeline. Bare evening remains a keyword; use period:evening for cross-date time filtering. Existing keyword matching uses any matching token, not Joplin's all-word semantics. Exact YYYY-MM-DD parsing now removes the complete date before keyword search, avoiding orphaned year digits. Original event IDs and source navigation remain intact.

## AudioRecorder — recording UX and validation

https://github.com/Dimowner/AudioRecorder

Upstream describes configurable recording formats, bookmarks, imports and waveforms, with coverage reporting. Useful next steps: clearer waveform/bookmark navigation and real-device interruption fixtures. Its ongoing architecture rewrite is not a requirement to rewrite LifeMemory. No code imported.

## sherpa-onnx — existing offline engine

https://github.com/k2-fsa/sherpa-onnx

Supports offline speech recognition, VAD and speaker diarization including Android. LifeMemory already integrates pinned 1.13.8. Prioritize noisy-room evaluation, known-speaker-count comparison and resource profiling before adding more engines. Engine models remain separate imports; diarization labels are not identity verification.

## whisper.cpp — optional benchmark candidate

https://github.com/ggml-org/whisper.cpp

Native offline Whisper inference and Android examples make it a useful comparative ASR candidate. Not integrated in this iteration. Compare Chinese/English transcripts, latency, RAM and battery on Xiaomi 13 Ultra before deciding whether a second native runtime is worth the APK/resource cost. Whisper transcription alone does not supply automatic speaker identities.

## Verification and boundaries

Use upstream licenses and pinned commits before any future source reuse. No code from these newly reviewed projects was copied. This iteration focuses on tested search behavior, not new recording or recognition accuracy claims. Real-device validation remains pending.
